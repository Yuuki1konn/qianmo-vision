# 测试与部署说明

## 1. 测试清单

- 识别测试：晴天/阴天/黄昏/夜间的道路与目标识别。
- 速度测试：统计平均推理时延与 FPS。
- 资源测试：内存占用、CPU/GPU 利用率、电量消耗。
- 稳定性测试：连续运行 30 分钟是否出现卡顿或内存泄漏。

## 2. 端侧优化策略

- 优先使用 `FP16 TFLite`，兼顾速度与输出稳定性。
- 若端侧仍偏慢，再尝试 `Dynamic Range Quantization TFLite`。
- 使用多线程（采集线程 + 推理线程 + 渲染线程）。
- 优先尝试 TFLite GPU Delegate。
- 推理线程始终处理最新一帧，避免排队导致画面滞后。
- 语音提醒必须做节流，同类提醒建议间隔 `3~5 秒`。
- 若性能不足，优先降低刷新频率与渲染分辨率，不要让主线程卡死。

## 3. APK 发布

1. 在 Android Studio 生成签名密钥。
2. 选择 `Build > Generate Signed Bundle/APK`。
3. 输出 `release` 包并进行真机回归测试。

## 4. 验收建议

- 农村道路独立场景连续测试里程 >= 20km。
- 高风险类别（行人、动物、坑洼）召回率单独统计。

建议导出命令：

```powershell
E:\conda\envs\rural_vision\python.exe scripts/export/export_segmentation_tflite.py --checkpoint runs/segmentation_bdd_city_idd_relaxed/best.pt --model-name unet --input-size 512 --output-dir runs/export/segmentation_relaxed_release2 --int8
```

当前已完成的导出产物：

- `runs/export/segmentation_relaxed_release2/segmentation.onnx`
- `runs/export/segmentation_relaxed_release2/segmentation_fp16.tflite`
- `runs/export/segmentation_relaxed_release2/segmentation_dynamic_range.tflite`
- `runs/export/segmentation_relaxed_release2/segmentation_fp32.tflite`

推荐部署顺序：

1. 优先上 `segmentation_fp16.tflite`
2. 若端侧帧率仍不足，再测试 `segmentation_dynamic_range.tflite`
3. `segmentation.onnx` 保留给 PC 端调试和一致性验证

当前验证结果：

- 已对 `segmentation_fp16.tflite` 做 5 张样本一致性验证
- 平均 `L1` 误差：`0.002983`
- 最大 `L1` 误差：`0.003290`
- 结论：与 `ONNX` 输出基本一致

说明：

- 当前环境若出现 `No module named 'tf_keras'`，需先补安装相关依赖后再执行导出。
- `onnx2tf` 在 Windows 下对 `UNet ConvTranspose` 和 `SavedModel` 路径处理有兼容性问题，脚本已做本地修复与离线兼容。
- 当前 `--int8` 实际导出的是 `Dynamic Range Quantization TFLite`，不是全整型校准版。
