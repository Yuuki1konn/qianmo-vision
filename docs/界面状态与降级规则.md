# 界面状态与降级规则

## 1. 主界面状态

主界面建议只保留一条底部状态文案。

推荐状态文案：

- `前方道路正常`
- `前方有行人`
- `前方有动物`
- `前方有坑洼`
- `前方有障碍物`
- `靠近道路边缘`
- `前方可行驶区域变窄`
- `识别已降级，请减速`

## 2. 状态显示优先级

从高到低建议如下：

1. `靠近道路边缘`
2. `前方有障碍物`
3. `前方有动物`
4. `前方有行人`
5. `前方有坑洼`
6. `前方可行驶区域变窄`
7. `前方道路正常`

说明：

- 同时触发多个状态时，只显示最高优先级的一条

## 3. 顶部状态栏建议

顶部建议分两行显示，但总信息仍然保持很少：

第一行：

- `识别中`
- `流畅 / 一般 / 降级`
- `语音开 / 语音关`

第二行：

- `仅分割`
- 或 `分割 + 检测`
- `检测未启用 / 检测已启用(ONNX) / 检测已启用(TFLite) / 检测启动失败`

不要再叠加更多调试信息给普通用户。

## 4. 性能分级规则

### 4.1 流畅

条件建议：

- 综合刷新率 `>= 15 FPS`
- 画面无明显滞后

显示：

- `流畅`

### 4.2 一般

条件建议：

- 综合刷新率 `10~15 FPS`
- 偶尔出现轻微延迟

显示：

- `一般`

### 4.3 降级

条件建议：

- 综合刷新率 `< 10 FPS`
- 或推理耗时持续过长

显示：

- `降级`
- 底部状态可切换为：`识别已降级，请减速`

## 5. 降级顺序

真机性能不足时，按以下顺序降级：

1. 降低渲染分辨率
2. 降低分割刷新频率
3. 切换分割模型为 `Dynamic Range TFLite`
4. 降低检测刷新频率
5. 减少低优先级目标显示

不要一开始就全部降级。

## 6. 推荐运行策略

- 相机线程持续采集
- 推理线程只处理最新一帧
- 渲染线程显示最近一次有效结果
- 不允许结果排队堆积

## 7. 模型使用建议

- 默认主模型：
  - `relaxed + segmentation_fp16.tflite`
- 备用模型：
  - `segmentation_dynamic_range.tflite`
- `strict`：
  - 不建议在普通模式下实时双跑

## 8. 当前最终建议

最终面向用户时，界面应满足：

- 字少
- 颜色少
- 状态明确
- 不闪烁
- 不堆信息

如果需要给老师或答辩展示开发能力，可以额外保留一个“调试模式”，显示：

- FPS
- 当前模型
- 检测数量
- 分割面积比例

但普通用户模式不要显示这些内容。
