# 检测模型接入检查清单

这份清单的目标很简单：

- 拿到 `detection.tflite` 后，不靠猜去改 Android 端
- 先确认张量信息
- 再决定解析器应该怎么调

当前 Android 端相关代码位置：

- [DetectionEngine.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionEngine.kt)
- [DetectionTensorInspector.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionTensorInspector.kt)
- [YoloV8TfliteDetectionParser.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/YoloV8TfliteDetectionParser.kt)
- [DetectionModuleFactory.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionModuleFactory.kt)

## 0. 当前默认检测源模型

当前项目里已经训练好的检测权重，不是空白状态。

目前建议优先记住这一版：

- `runs/detect/runs/detection/yolov8_rural_coarse_plus_pothole_idd_det_balanced_yolov8s_imgsz704/weights/best.pt`

它对应的是：

- `YOLOv8s`
- `imgsz=704`
- `pothole`
- `IDD_Detection` 补样本版本

说明：

- Android 端当前缺的不是检测权重
- 缺的是可直接放进 `assets` 的检测部署模型，例如 `detection.tflite`

## 1. 先放模型

把导出的检测模型放到：

- `android/app/src/main/assets/detection.tflite`

当前默认配置在：

- [AppConfig.kt](../android/app/src/main/java/com/qianmo/ruralvision/config/AppConfig.kt)

## 2. 先看张量，不要急着改解析器

先用 [DetectionTensorInspector.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionTensorInspector.kt) 读取模型报告。

你要重点确认 4 件事：

1. 输入张量数量是不是 `1`
2. 输入形状是不是接近 `[1, 704, 704, 3]`
3. 输出张量数量是不是 `1`
4. 输出形状是不是 YOLO 常见格式

常见情况：

- `[1, 10, 8400]`
- `[1, 8400, 10]`
- `[1, 84, 8400]`
- `[1, 8400, 84]`

其中：

- `10 = 4框参数 + 6类`
- 如果还有 `objectness`，则可能变成 `11`

## 3. 现在这版解析器默认假设

[YoloV8TfliteDetectionParser.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/YoloV8TfliteDetectionParser.kt) 当前默认假设：

- 输出只有 `1` 个张量
- 数据类型是 `FLOAT32`
- 输出格式是：
  - `[1, attrs, count]`
  - 或 `[1, count, attrs]`
- 坐标默认是按输入尺寸的像素值表达
- 当前类别数固定按 `6` 类处理

类别顺序与训练侧保持一致：

- `0 -> two_wheeler`
- `1 -> pedestrian`
- `2 -> animal`
- `3 -> barrier`
- `4 -> pothole`
- `5 -> tricycle`

## 4. 什么情况下不用改

如果你的检测模型满足下面这些条件，通常不用大改：

- `output_count = 1`
- `dtype = FLOAT32`
- `shape` 能对应到 `4 + cls` 或 `5 + cls`
- `cls = 6`
- 坐标不是 `0..1`，而是按输入尺寸范围给出

这时通常只需要：

- 把 `AppConfig.Detection.ENABLED` 改为 `true`
- 保持 [DetectionModuleFactory.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionModuleFactory.kt) 默认配置

## 5. 什么情况下要改

### 情况 A：坐标已经是归一化的

如果你发现输出框坐标本来就是 `0..1`，那就把：

- [DetectionModuleFactory.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionModuleFactory.kt)

里的：

- `coordinatesNormalized = false`

改成：

- `coordinatesNormalized = true`

### 情况 B：输出没有 objectness

如果 `attrs = 4 + cls`，当前解析器也能处理，不用额外改。

### 情况 C：输出有多个张量

如果输出不止一个张量，比如：

- boxes 一个张量
- scores 一个张量
- classes 一个张量

那就不能继续用当前的单张量 YOLO 模板，需要：

- 新写一个 `DetectionOutputParser`
- 在 [DetectionModuleFactory.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionModuleFactory.kt) 里切换过去

### 情况 D：类别数不是 6

如果后面重新训练了检测模型，类别数发生变化，需要同步修改：

- [DetectionModuleFactory.kt](../android/app/src/main/java/com/qianmo/ruralvision/inference/DetectionModuleFactory.kt) 里的 `numClasses`
- [AppConfig.kt](../android/app/src/main/java/com/qianmo/ruralvision/config/AppConfig.kt) 里的 `Detection.Classes`
- [DriveStateEvaluator.kt](../android/app/src/main/java/com/qianmo/ruralvision/domain/DriveStateEvaluator.kt) 的提醒逻辑

## 6. 建议的接入顺序

1. 放入 `detection.tflite`
2. 运行张量检查，记录输入输出形状
3. 对照这份清单判断是否需要改解析器
4. 确认类别顺序
5. 把 `Detection.ENABLED = true`
6. 先只看框位置是否正确
7. 再调语音和风险规则

## 7. 第一轮只验证这几项

第一轮不要一下子追求“全部都好”，只先看：

- 框有没有画出来
- 框位置是不是基本对
- 行人/动物/坑洼/障碍物类别有没有明显串类
- 帧率有没有明显掉到不可用

## 8. 如果接上后很卡

优先这样降级：

1. 保持分割主链不变
2. 让检测每 `3` 帧或 `5` 帧跑一次
3. 先不做复杂后处理
4. 只保留高风险类别播报

这部分当前已经在配置里预留：

- [AppConfig.kt](../android/app/src/main/java/com/qianmo/ruralvision/config/AppConfig.kt)
