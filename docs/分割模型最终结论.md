# 分割模型最终结论

## 1. 目标

本项目的分割模型用于输出农村二轮车行驶场景中的可行驶区域。由于“可行驶”本身存在保守定义与宽松定义两种需求，因此最终采用“双模型定位”方案。

## 2. 数据集选择结论

### 2.1 不再作为主监督的数据

- `RUGD`
  - 原因：`RUGD` 更接近地表材质/场景语义数据，而不是稳定的道路可行驶语义。
  - 典型问题：某些图中 `dirt / gravel / sand` 可以近似道路，但在另一些图中这些类别并不等于“安全可通行道路”。
  - 结论：`RUGD` 不适合作为主分割模型的直接监督数据。

### 2.2 作为主监督的数据

- `BDD100K drivable maps`
  - 具有明确的可行驶区域定义。
- `Cityscapes`
  - 采用 `road` 作为正类，标签稳定。
- `IDD`
  - 使用 `road` 与 `drivable fallback` 构造道路二值掩码，适合补充非结构化道路环境。

## 3. 两版模型的定位

### 3.1 保守版 strict

- 配置文件：
  - [segmentation_bdd_city_idd_refined.yaml](../configs/segmentation_bdd_city_idd_refined.yaml)
- 模型文件：
  - `runs/segmentation_bdd_city_idd_refined/last.pt`
- 设计思路：
  - `BDD` 仅使用 `direct drivable` 作为正类。
  - 优先保证安全边界，不主动扩大到可选换道区域。
- 适用场景：
  - 作为保守安全边界参考。
  - 用于约束风险、避免过度乐观输出。

### 3.2 宽松版 relaxed

- 配置文件：
  - [segmentation_bdd_city_idd_relaxed.yaml](../configs/segmentation_bdd_city_idd_relaxed.yaml)
- 模型文件：
  - `runs/segmentation_bdd_city_idd_relaxed/best.pt`
- 设计思路：
  - `BDD` 使用 `direct drivable + alternative drivable` 作为正类。
  - 允许将同向可换道区域也纳入候选可通行区。
- 适用场景：
  - 作为主显示模型。
  - 更符合实际驾驶直觉，也更适合展示整体道路通行空间。

## 4. 指标结果

### 4.1 strict 版

- 训练过程后期验证日志最佳区间：
  - `mIoU` 约 `0.7471`
  - `Dice` 约 `0.8529`
- 使用完整评估脚本重算：
  - `mIoU: 0.7862`
  - `Dice: 0.8759`
  - `Pixel Accuracy: 0.9672`

说明：

- 训练日志与独立评估脚本的口径不同，因此数值不能机械一一对齐。
- 但整体结论一致：strict 版更保守，边界更收缩。

### 4.2 relaxed 版

- 训练日志最佳结果：
  - `Epoch 100`
  - `mIoU = 0.8411`
  - `Dice = 0.9128`
  - `PA = 0.9715`

结论：

- relaxed 版在视觉效果与指标上都优于 strict 版，更符合项目当前的道路显示需求。

## 5. 最终选择

### 主模型

- 选择 `relaxed` 版作为主分割模型。
- 原因：
  - 更符合人对“同向可换道区域”的直觉。
  - 在 `BDD / Cityscapes / IDD` 的抽样可视化中，整体道路连贯性更好。
  - 对项目展示和后续集成更友好。

### 辅助模型

- 保留 `strict` 版作为安全边界参考模型。
- 原因：
  - 当需要更保守的风险收缩策略时，可以作为对照与补充。

## 7. 工程建议

- 若系统仅输出一个分割结果，优先使用 `relaxed`。
- 若系统支持双层语义输出，可采用：
  - `relaxed`：候选可通行区域
  - `strict`：安全边界参考
- 后续若继续提升质量，优先方向不是继续混入 `RUGD`，而是补充更贴近农村道路语义的自采集标注数据。
